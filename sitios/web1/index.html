Tu mini data center, en vivo

Cada punto luminoso es una petición HTTP. Entra por el puerto 8080 del host, llega al balanceador y este la reenvía a un nodo de la granja_web. En la simulación puedes hacer clic en un nodo para apagarlo y ver cómo el balanceador lo esquiva.

petición HTTP tráfico de la app logs (stdout → Alloy → Loki) Clic en un nodo = encender / apagar (simulación)
Tu navegador pidehttp://localhost:8080. El host reenvía ese puerto al contenedor lb (mapeo 8080:80).
El balanceador eligeNginx aplica el algoritmo del bloque upstream granja_web: round robin, pesos, least_conn o ip_hash.
Un nodo respondeCada nodo tiene su propia carpeta (volumen) y firma la respuesta con la cabecera X-Nodo.
Todo queda registradoLa bitácora JSON viaja a Loki y se ve en Grafana; visitas y pruebas se guardan en MariaDB.

Guarda 2 o 3 pruebas y luego, en la terminal:

# 3) Ahora destruye TAMBIÉN los volúmenes
docker compose down -v
docker compose up -d

Inspecciona dónde vive físicamente el volumen: 

docker volume ls

Alloy + Loki logs

Alloy lee la salida de cada contenedor (vía docker.sock) y la envía a Loki, que la indexa por etiquetas. Prueba en Grafana → Explore:

{servicio="lb"} | json | nodo="web2"
Principio¿Dónde lo aplicamos en este ejercicio?
CConfidencialidad Contraseñas en .env (fuera del código y del repositorio) · Grafana sin registro libre ni acceso anónimo · MariaDB publicada solo en 127.0.0.1:3306 · los nodos web no ven la red_datos.
IIntegridad Sitios montados en solo lectura (:ro) · usuarios de BD con mínimo privilegio (app_user: SELECT/INSERT; grafana_ro: SELECT) · consultas parametrizadas y validación en la API · límite de 64 KB por petición.
ADisponibilidad Tres réplicas detrás de un balanceador · max_fails + proxy_next_upstream (failover) · restart: unless-stopped · healthchecks · volúmenes persistentes y rotación de logs.

Retos: zonas editables

Predice el resultado en el modo simulación, haz el cambio real, compruébalo en el laboratorio y en Grafana, y documenta todo en tu bitácora (captura + explicación).

1

Dale personalidad a tu nodo

Básico

Cambia nombre, color y mensaje de web2. Guarda y recarga con F5 hasta que te toque web2.

Ves el cambio sin reiniciar: la carpeta es un bind mount. Para que /whoami también cambie, edita NODO_NOMBRE/NODO_COLOR en el compose y ejecuta docker compose up -d web2.
2

Pesos: un nodo más potente

Básico
nginx/lb.conf · ZONA 2 
server web1:80 resolve weight=3 max_fails=2 fail_timeout=10s;
docker compose exec lb nginx -t        # valida
docker compose exec lb nginx -s reload  # aplica sin cortar
Con 30 peticiones: ≈ 18 / 6 / 6 (60 % · 20 % · 20 %).
3

Cambia el algoritmo

Intermedio
nginx/lb.conf · ZONA 1

Descomenta ip_hash;, recarga Nginx y lanza 30 peticiones. Repite con least_conn; y concurrencia 8. Actualiza el texto de /lb-info.

ip_hash: las 30 caen en un solo nodo (tú eres un solo cliente). ¿Para qué sirve esa “afinidad de sesión”?

Intermedio
terminal

0 fallos: el tráfico se reparte entre web1 y web3. En Grafana, la serie de web2 se corta y luego regresa.
5

Agrega un 4.º nodo

Intermedio
docker-compose.yml · lb.conf · comun/config.js

Copia la carpeta sitios/web3 como sitios/web4, duplica el servicio web3 como web4, añade server web4:80 resolve; y el nodo en config.js.

docker compose up -d web4
docker compose exec lb nginx -s reload
El diagrama dibuja el nuevo nodo y el reparto pasa a ≈ 25 % cada uno.
6

Escalamiento horizontal con --scale

Avanzado
docker-compose.yml · lb.conf

Reemplaza web1–web3 por un solo servicio web con NODO_ID: auto, y en el upstream deja solo server web:80 resolve;.

docker compose up -d --scale web=5
El DNS de Docker devuelve 5 IPs y Nginx (con resolve) las balancea. La página identifica cada réplica por su contenedor.

Comandos clave

Levantar todo (construye la imagen de la API)

docker compose up -d --build

¿Están todos “healthy”?

docker compose ps

Ver la bitácora del balanceador en vivo

docker compose logs -f lb

Preguntar “¿quién soy?” al balanceador

curl -s http://localhost:8080/whoami

Validar y recargar Nginx sin cortar el servicio

docker compose exec lb nginx -t && docker compose exec lb nginx -s reload

Apagar / encender un nodo

docker compose stop web2 && docker compose start web2

Entrar a MariaDB como root

docker compose exec db mariadb -uroot -p dc_app

Consumo de CPU/RAM por contenedor

docker stats --no-stream

Listar e inspeccionar volúmenes

docker volume ls && docker volume inspect minidc_db_data

Apagar todo (conservando datos)

docker compose down
